# How I Think About Engineering

### Build for production

Writing code is only one part of the job.

I care about what happens after deployment:

**security → reliability → observability → failure handling → maintainability**

### Isolate environments

Development, staging, and production should have clear boundaries.

The same principle should apply to credentials, permissions, infrastructure, and data.

### Prefer identity over static credentials

Where supported, I prefer mechanisms such as **Application Default Credentials (ADC), workload identity, and short-lived credentials** over distributing long-lived service-account keys.

### Infrastructure should be reproducible

Infrastructure should be:

* Defined as code
* Reviewable
* Repeatable
* Version controlled
* Recoverable

Manual infrastructure changes should be the exception, not the system.

### Architecture should serve the system

I prefer pragmatic architecture.

The goal isn't to create the most complicated architecture possible. The goal is to create a system that is **understandable, secure, maintainable, and capable of evolving**.
